主流程固定为五步：Idea、Concept、Blueprint、Chapter Plan、Chapter Workspace。Chapter Workspace 是单一页面：左侧 Chapter → Scene 两级列表；中间显示章节概况、Scene 描述和 Beat 卡片；右侧默认显示少量状态，点击后可展开全局状态面板。

01 · 五步页面流程

1 User Idea→2 Story Concept→3 Story Blueprint→4 Chapter Plan→5 Chapter Workspace→Next Chapter
步骤页面职责进入条件
1 User Idea作者输入一句或多句话的创作目标。始终可开始或编辑原始 Idea。
2 Story Concept确认类型、风格、长度、视角及核心内容。由 Idea 生成候选。
3 Story Blueprint确认 Characters、World、Initial Timeline、Story Arc 和 Living State。Concept 已确认。
4 Chapter Plan查看章节卡片；第一章固定并激活，后续章节是可演化雏形。Blueprint 已确认。
5 Chapter Workspace同一页完成当前章节的 Scene、Beat、正文生成、Delta 和状态更新。用户点击当前已激活章节。

02 · 核心交互规则

统一五步导航

所有 Story Blueprint、Chapter Plan 和 Chapter Workspace 页面显示同一套 1–5 导航。进入当前章节后，只有第 5 步点亮；不再出现 5A / 5B 两个步骤。

工作台一页完成

章节规划与写作不是两个页面。Scene 选择、Beat 规划、生成、重新生成、正文查看、Delta 和状态检查共存于 Chapter Workspace。

信息密度可控

Beat 内容使用固定高度滚动区域，避免单个 Beat 无限撑长页面；Beat banner 可展开或收缩，默认只展开当前 Beat。

Chapter Workspace 是唯一章节页面。左侧只显示 Chapter → Scene 两级；Beat 不进入左侧导航，而在选中 Scene 的正文区内以固定高度、可展开收缩的卡片呈现。右侧状态栏默认窄显示，展开后覆盖式展示 Blueprint 级别全貌。

04 · 状态面板交互

默认窄状态栏

只占工作台右侧少量比例，显示 Snapshot、Scene 完成度、Delta 候选和检查数量。不干扰正文阅读。

展开全貌面板

点击“展开全局状态”后覆盖工作台内容区，可查看角色状态、世界状态、时间线、剧情线和 Delta 来源。

与 Blueprint 一致

展开面板的数据分类与 Blueprint 完全相同：Characters、World、Initial Timeline、Story Arc / Living State，避免两套状态解释。

面板规则：展开不离开 Chapter Workspace；面板关闭后保留当前 Scene、Beat 展开状态和滚动位置。移动端改为全屏覆盖层，使用“返回工作台”关闭。

06 · 开发交付顺序与验收

前端组件

  1. 统一五步 flow-nav：Idea、Concept、Blueprint、Chapter Plan、Chapter Workspace。
  2. scene-list：Chapter → Scene 两级，禁止 Beat 进入左侧树。
  3. beat-card：banner、展开收缩、固定高度正文滚动、生成/重生成操作。
  4. status-rail 与 state-overlay：窄状态栏和覆盖式全貌面板。

必须通过的 UI 验收

  • 进入指定章节后只点亮第 5 步“章节工作台”。
  • 不存在 5A / 5B 两个导航步骤或两个章节页面。
  • 左侧只有 Chapter 和 Scene 两级；Beat 全部位于右侧内容区域。
  • Beat 正文区域固定高度，超出内容滚动，不无限拉长页面。
  • 默认状态面板窄显示；展开后覆盖式展示 Blueprint 级别完整故事状态。
  • 关闭全貌面板后回到同一 Scene、Beat 和滚动位置。

Snapshot 三大域与 Chapter Events 是 Blueprint 的状态入口，也是 AI 生成 Chapter Context 的结构化来源；展开面板时使用同一套分类和字段。

状态条目可追溯

每条状态显示 subject、path、source、时间范围、confirmed / inferred / proposed 和 context policy。

事件计划与事实分离

Event 只描述计划；正文产生的 actual result 通过 Delta 检查后才进入 Living State。

AI 连续写作边界

下一 Beat 可读取前序已确认或当前 Scene 临时状态，但不能读取未来 Scene 的 Snapshot、Event 结果或后续章节信息。

05 · 状态面板交互

默认窄状态栏

只占工作台右侧少量空间，显示 Snapshot 有效性、Scene 完成度、Delta 候选和检查数量。

展开全貌面板

点击“展开全局状态”后覆盖工作台内容区，可查看 Character State、World State、Timeline State 和 Chapter Events。

与 Blueprint 一致

展开面板复用 Blueprint 的状态分类、字段和来源引用，不建立另一套状态解释。

面板规则：展开不离开 Chapter Workspace；关闭后保留当前 Scene、Beat 展开状态和滚动位置。移动端改为全屏覆盖层。

07 · 开发交付顺序与验收

前端组件

  1. 统一五步 flow-nav：Idea、Concept、Blueprint、Chapter Plan、Chapter Workspace。
  2. Blueprint State Snapshot 三域组件：Character / World / Timeline。
  3. Chapter Events 表格：planned result、actual result、state impacts、source。
  4. Chapter Workspace 的窄状态栏和全貌覆盖面板。
  5. 状态条目显示来源、时间范围、确认级别和上下文策略。

必须通过的 UI 验收

  • Blueprint 页面能分别查看 Character State、World State、Timeline State。
  • Chapter Events 不与 Story State 混合，并显示计划与实际结果。
  • State Snapshot 明确章前时间边界，不能展示未来信息。
  • 状态候选显示 proposed，确认后才进入 Living State。
  • Chapter Workspace 展开的全貌面板与 Blueprint 使用同样分类和字段。
